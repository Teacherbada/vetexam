# PDF 分批匯入

PDF 解析完成後，可在確認匯入旁啟用「分批匯入」，設定每批的起訖題號，例如 1–40、41–80。題號以畫面目前的題目排列為準，所有範圍必須連續、不重疊且涵蓋全部題目。系統預設分成兩批，也可以新增批次。

按下分批匯入後，系統先檢查每批 JSON（包含圖片）的 UTF-8 大小，再依序送出。單批上限為 4,000,000 bytes；超過時需縮小該批範圍，單題超過時需縮小圖片。一般儲存若超過此上限，會自動開啟分批設定，保留解析結果。

所有批次成功後，才一次建立同一份題庫，保留年份、科目、題目順序、選項、答案、解析及圖片。尚未載入的題目圖片會提示先完成預覽。過程失敗時保留畫面，可在同一頁重試；相同內容的重試沿用匯入識別碼，不會重複建立題目。重新整理頁面不提供續傳；修改內容或範圍會建立新的匯入工作。

此功能處理解析後的儲存容量，最初 PDF 上傳若已超過平台限制，仍需先縮小 PDF。PDF Parser、既有一般儲存 API、錯題、收藏及統計流程不變。

## 資料庫

`migrations/20260912_pdf_batch_imports.sql` 新增兩個暫存工作表，沒有修改既有資料表。部署前執行 `node scripts/migrate-pdf-batches.mjs --apply`；不加 `--apply` 為交易回滾的試跑。完成後清除暫存題目內容，只保留重試所需的雜湊。使用者後續發起匯入時，清理其超過七天的未完成工作。

## 驗證

- `npx tsc --noEmit`
- `npm run build`
- `node --test tests/pdf-batches.test.mjs`
- 設定 `PDF_BATCH_DB_TEST=1` 後執行上述測試，可驗證真實 PostgreSQL 交易、順序、權限、失敗回滾與重試。測試資料使用獨立 schema，最後回滾。
- `node tests/pdf-batches-browser.mjs`：需本機 Playwright 與 Edge，預設網站為 `http://localhost:3200`。可使用 `PLAYWRIGHT_MODULE` 指定 Playwright 模組路徑；瀏覽器測試以 mock API 驗證容量檢查、手機排版、範圍驗證、依序送出、失敗重試及純文字 413，不寫入正式題庫。
